## 一、安全基础设施（Nginx 透传 + IP 日志 + IP 封禁）

### 1.1 Nginx 透传修复

```
□ 确认 nginx.conf 的 proxy_set_header X-Real-IP / X-Forwarded-For 在生产环境生效
□ 后端启动参数加 --proxy-headers 让 uvicorn/FastAPI 读取代理头
□ 或加 Starlette ProxyHeadersMiddleware 中间件
□ 写工具函数 get_real_ip(request) 统一取 IP（优先 X-Real-IP → X-Forwarded-For → request.client.host）
□ 替换 auth/routes.py 等现有代码中的 request.client.host
□ 验证 docker-compose 环境下的 IP 透传链路
```

### 1.2 结构化 IP 请求日志

```
□ 数据库模型 RequestLog：
  - id, ip, method, path, status_code, user_agent, referer, duration_ms, created_at
  - 可选：user_id, region, isp
□ RequestLogMiddleware：每个请求经过时记录
□ 计数器聚合表 IpActionCounter：
  - ip, action（行为分类如 login_fail/api_call/page_view）, date, hour, count
  - 按固定窗口聚合，明细 TTL 清理
□ APScheduler 定时任务：明细 → 聚合归并
□ 前端管理页面：IP 行为查询（按 IP / 时段 / 行为分类）
□ 前端可视化：TOP IP、异常行为趋势图
```

### 1.3 IP 封禁系统

```
□ 数据库模型 IpBan：
  - id, ip_or_cidr, ban_type (auto|manual), reason, rule_id, banned_by, created_at, expires_at, is_active
□ IPv4 支持：单 IP + CIDR 段（192.168.1.0/24）
□ IPv6 支持：单 IP + CIDR 段（2001:db8::/32）
□ IpBanMiddleware 中间件：
  - 每请求查 IP 是否在封禁列表
  - LRU 缓存 + 布隆过滤器加速
  - CIDR 匹配用 ipaddress 标准库
□ 地域/运营商特征库：
  - 评估是否引入 MaxMind GeoLite2
  - 或用简易策略从请求特征推断
□ 自动封禁规则引擎 IpAutoBanRule：
  - 规则 1：同 IP 5 分钟内登录失败 ≥ N 次 → 封 30 分钟
  - 规则 2：同 IP 1 小时内 4xx ≥ N 次 → 封 1 小时
  - 规则 3：同 IP 1 分钟请求 ≥ N 次 → 限流/封禁
  - 规则 4（预警）：同地域/运营商 IP 突增 → 告警通知
  - 规则引擎可配置阈值、可启停
□ 手动封禁管理：
  - 输入 IP/CIDR、选择时长、填写原因
  - 批量封禁、解封
  - 封禁操作日志
□ 封禁通知：钉钉/飞书 webhook（可选）
□ 前端 IP 管理页面：
  - 封禁列表（分页/搜索/筛选）
  - 封禁/解封操作
  - 封禁历史日志
  - 自动封禁规则配置面板
```

## 二、编辑流程打磨

### 2.1 MD 文件解析（核心难点 - 千人千面）

```
□ 现状 parseImportFile.ts 仅支持 .md/.txt，策略简单
□ 兼容多种 MD 方言：GFM / CommonMark / TOML frontmatter / YAML frontmatter
□ 混合格式兼容：同文档不同风格混写
□ 代码块多标记：```  ~~~  4 空格缩进
□ 表格解析：|---| 格式转为结构化段落
□ 任务列表：- [ ] / - [x]
□ 锚点/脚注：[^1] 形式
□ HTML 混写处理策略
□ 数学公式：$...$ / $$...$$ 保留或渲染
□ 图片多形式：相对路径 / URL / Base64
□ 链接引用：[label][ref] + 底部 [ref]: url
□ 解析模式选择：
  - "严格模式"按标准 MD 解析
  - "宽松模式"尽量猜意图
  - 导入预览：先展示结果再确认填充
□ 解析质量保障：
  - 测试用例覆盖多种 MD 风味
  - 测试驱动开发
```
